# Report Desk — نسخهٔ دوم

سیستم مدیریت صنف، نصاب، گزارش هفتگی، اساتید و نگران‌ها با Next.js App Router، TypeScript و MongoDB. رابط فارسی با تقویم هجری شمسی و RTL، رابط انگلیسی با تقویم میلادی و LTR، ساعت ۱۲ساعته و تم روشن/تاریک دارد.

## ورود ایمیلی و دعوت سرنگران‌ها

ورود فقط با ایمیل و کد یک‌بارمصرف شش‌رقمی انجام می‌شود. کد ۵ دقیقه اعتبار و حداکثر ۵ تلاش دارد؛ ارسال دوباره پس از یک دقیقه مجاز است و کد قبلی را باطل می‌کند. کدها به‌شکل هش نگهداری می‌شوند و پس از مصرف قابل استفادهٔ دوباره نیستند. محدودیت درخواست‌ها در دیتابیس ذخیره می‌شود تا میان اجرای چند سرور مشترک باشد.

ادمین سیستم فقط ایمیل تأییدشدهٔ `elyasqati527@gmail.com` است. اولین ورود موفق این ایمیل، حساب و فضای کاری خالی تازه‌ای می‌سازد. حساب‌ها، رمزهای قبلی و مالکیت داده‌های قدیمی منتقل یا حذف نمی‌شوند؛ ورود با نام کاربری/رمز و نشست‌های قدیمی دیگر پذیرفته نمی‌شود. اتصال حساب قدیمی به ایمیل در این تغییر انجام نمی‌شود.

ادمین از «مدیریت دعوت‌ها» ایمیل شخص و مدت اعتبار را مشخص می‌کند و کد دعوت می‌سازد. کد فقط یک بار نمایش داده می‌شود تا ادمین آن را برای همان شخص بفرستد. هر دعوت مخصوص یک ایمیل، دارای کد تصادفی بلند و یک‌بارمصرف است و تا پیش از استفاده قابل لغو است. کاربر جدید از ثبت‌نام، نام کامل، ایمیل و کد دعوت را وارد و سپس OTP دریافتی را تأیید می‌کند. حساب و تنظیمات خالی فقط پس از تأیید ساخته و دعوت هم‌زمان در تراکنش مصرف می‌شود. ورودهای بعدی به دعوت جدید نیاز ندارند. دعوت منقضی یا لغوشده، حتی اگر OTP پیش‌تر ارسال شده باشد، حساب نمی‌سازد.

صنف‌ها، اساتید، نگران‌ها، نصاب‌ها، گزارش‌ها، آرشیف، تنظیمات، آمار و بکاپ هر حساب جدا هستند؛ ادمین سیستم نیز اطلاعات کاری دیگران را از این بخش نمی‌بیند. شناسهٔ مالک از نشست معتبر گرفته می‌شود؛ ارسال مالک یا نقش دلخواه در درخواست دسترسی ایجاد نمی‌کند. خروج یا تعویض حساب، برگه‌های دیگر مرورگر را هم به‌روز می‌کند.

## نقش سرنگران و مانیتور

در صفحهٔ ورود «سرنگران هستم» برای ورود ایمیلی فعلی و «مانیتور هستم» برای ورود تنها با کد دسترسی است. حساب‌های قبلی سرنگران و اطلاعات‌شان حفظ می‌شوند؛ نقش قدیمی `member` نیز در رابط به‌صورت سرنگران شناخته می‌شود.

هر سرنگران از بخش «دسترسی مانیتور» یک کد فعال اختصاصی می‌سازد و خصوصی برای مانیتور خود می‌فرستد. کد تصادفی طولانی فقط هنگام ایجاد نمایش داده می‌شود و تا زمان لغو یا تعویض معتبر است. کدهای فعلی و قبلی در تمام فضاها یکتا می‌مانند؛ در دیتابیس فقط هش آن‌ها ذخیره می‌شود. تعویض کد به‌صورت اتمی انجام می‌شود و هم‌زمان کد قبلی و تمام نشست‌های وابسته به آن بی‌اعتبار می‌شوند. نشست مانیتور حداکثر هفت روز اعتبار دارد و سپس با همان کد فعال می‌تواند دوباره وارد شود.

مانیتور حساب کاربری و ایمیل ندارد. نشست او به صاحب کد متصل است و در هر درخواست، فعال‌بودن دسترسی و حساب سرنگران بررسی می‌شود. او اطلاعات همان سرنگران را از رابط جداگانه می‌بیند: گزارش‌ها، صنف‌ها، اساتید، نگران‌های صنف، کتاب‌ها، عناوین درس، تحلیل و آرشیف. جست‌وجو، فیلتر دوره، مشاهدهٔ جزئیات و خروجی گزارش‌ها مجاز است؛ افزودن، ویرایش، حذف، آرشیف، بازیابی، تنظیمات، بکاپ خام و مدیریت دعوت/کد در API هم مسدود است. مانیتور دسترسی ادمین را به ارث نمی‌برد، حتی اگر کد از فضای ادمین صادر شده باشد.

این کد یک اعتبار دسترسی قابل اشتراک است: هر شخصی که آن را داشته باشد می‌تواند اطلاعات همان فضا را مشاهده کند. این روش هویت یا تعداد اشخاص استفاده‌کننده از کد را شناسایی نمی‌کند؛ تنها یک کد فعال برای هر سرنگران وجود دارد. از کد مانند رمز نگهداری کنید. رابط مانیتور هنگام فعال‌بودن صفحه هر ۱۵ ثانیه و هنگام بازگشت به صفحه تازه می‌شود؛ لغو دسترسی از همان لحظه در سرور اعمال می‌شود.

برای این قابلیت متغیر محیطی یا سرویس تازه لازم نیست. ایندکس‌های لازم هنگام ایجاد یا ورود با کد خودکار آماده می‌شوند؛ `npm run setup` نیز آن‌ها را می‌سازد. در Vercel نسخهٔ جدید را دیپلوی کنید و تنظیمات MongoDB و SMTP فعلی را نگه دارید.

## اجرا

Node.js 22 یا جدیدتر پیشنهاد می‌شود.

دستورها را از ریشهٔ پروژه، کنار فایل `package.json`، اجرا کنید.

```powershell
npm install
# فایل .env.example را به .env کپی و اتصال MongoDB و تنظیمات SMTP را مشخص کنید.
npm run setup
npm run dev
```

نشانی: http://localhost:3000/fa و http://localhost:3000/en

اگر پورت ۳۰۰۰ اشغال باشد، Next.js پورت دیگری مثل ۳۰۰۱ انتخاب می‌کند؛ نشانی بخش `Local` در ترمینال را باز کنید، مثلاً http://localhost:3001/fa. آدرس `0.0.0.0` برای گوش‌دادن سرور روی شبکه است؛ در مرورگر همین سیستم از `localhost` استفاده کنید. برای بستن اجرای قبلی، در ترمینال همان اجرا `Ctrl+C` بزنید.

`setup` فقط ایندکس‌ها را آماده می‌کند و حساب یا مالکیت اطلاعات قدیمی را تغییر نمی‌دهد. ایندکس‌های احراز هویت هنگام اولین درخواست نیز آماده می‌شوند. برای تراکنش ساخت حساب و مصرف دعوت، MongoDB replica set لازم است؛ Atlas این قابلیت را دارد. حساب MongoDB باید روی دیتابیس `report_desk` دسترسی خواندن/نوشتن و ساخت ایندکس داشته باشد.

### ارسال ایمیل و Vercel

- `SMTP_USER=elyasqati527@gmail.com`
- `SMTP_PASS`: App Password همین جیمیل؛ رمز عادی Gmail نیست. ابتدا تأیید دومرحله‌ای Google فعال شود.
- `SMTP_HOST=smtp.gmail.com` و `SMTP_PORT=465` (پیش‌فرض).
- `MONGODB_URI` و `MONGODB_DB` نیز مانند قبل تنظیم شوند.

متغیرهای SMTP باید در Vercel برای Production و هر محیط مورد استفاده تنظیم شوند و پس از تغییر، Redeploy انجام شود. اطلاعات SMTP پروژهٔ مرجع مربوط به فرستندهٔ دیگری بود و کپی نشده است. رمزها و `.env` نباید در Git قرار بگیرند. برای بررسی اتصال SMTP بدون ارسال ایمیل، `npm run check:mail` اجرا شود. خطاهای تنظیم‌نبودن ایمیل و شکست ارسال به‌صورت مجزا در رابط نمایش داده می‌شوند؛ جزئیات محرمانهٔ SMTP در لاگ چاپ نمی‌شوند.

## ساختار

- `src/app/api`: احراز هویت، API موجودیت‌ها، تنظیمات و پشتیبان‌گیری/بازیابی.
- `src/lib`: اتصال دیتابیس، اعتبارسنجی Zod، تقویم، منطق آمار و رتبه‌بندی.
- `src/components`: رابط کاربری، فرم‌ها، نمودارها و صفحات.
- `scripts`: راه‌اندازی و انتقال SQL قدیمی.
- `tests`: آزمون تقویم، اعتبارسنجی و رتبه‌بندی.

## منطق زمان و آمار

- هفته از جمعه شروع می‌شود و پنج‌شنبه ساعت ۱۱:۵۹ شب به وقت کابل پایان می‌یابد.
- تاریخ‌ها در دیتابیس به‌شکل میلادی `YYYY-MM-DD` ذخیره می‌شوند؛ تقویم شمسی فقط تبدیل نمایشی/انتخاب تاریخ است.
- فیلتر ماه شامل سال و تقویم انتخاب‌شده است؛ مرز ماه شمسی به تاریخ میلادی تبدیل می‌شود.
- هر صنف در هر هفته یک گزارش فعال دارد. ایندکس یکتا از ثبت تکراری هم‌زمان جلوگیری می‌کند.
- زمان اولین ارسال با ویرایش تغییر نمی‌کند. صنف یا هفتهٔ یک گزارش تاریخ‌دار قابل جابه‌جایی نیست.
- «ثبت‌نام صنف‌ها» مجموع ظرفیت فعلی صنف‌ها است و تعداد افراد یکتا نیست. «مجموع حاضری» تعداد حضور در گزارش‌ها است.
- نرخ حاضری = مجموع حاضران / مجموع شاگردان مورد انتظار، نه میانگین سادهٔ درصد صنف‌ها.
- رتبه‌بندی به‌صورت پیش‌فرض ۸ هفتهٔ تکمیل‌شده را بررسی می‌کند: ۵۰٪ گزارش به‌موقع، ۳۵٪ حاضری، ۱۵٪ ثبات حاضری. هفتهٔ باز کنار گذاشته می‌شود و هفتهٔ بدون گزارش امتیاز را کم می‌کند. بدون سابقهٔ کافی، امتیاز «—» است.
- تغییر مسئول صنف برای تاریخچه ثبت می‌شود و مشخصات مسئول هنگام گزارش نیز حفظ می‌شود.
- آرشیف صنف به گزارش‌های آن به ارث می‌رسد؛ بازیابی صنف گزارش‌های مستقلاً آرشیف‌شده را بازنمی‌گرداند.
- عناوین درس شناسهٔ ثابت و بازهٔ صفحه دارند. عنوان استفاده‌شده در گزارش قابل حذف نیست.

## انتقال نسخهٔ قدیمی

```powershell
npm run migrate -- "E:\gozaresh_db.sql"
# پس از بررسی پیش‌نمایش؛ مقصد باید خالی باشد:
npm run migrate -- "E:\gozaresh_db.sql" --apply
# برای واردکردن در حساب دیگری که از قبل ساخته شده است:
npm run migrate -- "E:\gozaresh_db.sql" --apply --username=supervisor2
```

این ابزار SQL را اجرا نمی‌کند؛ فقط داده‌های INSERT سه جدول شناخته‌شده را می‌خواند. سال و زمان ارسال برای دادهٔ بدون تاریخ حدس زده نمی‌شود. گزارش‌های بدون تاریخ در بخش گزارش‌های قدیمی باقی می‌مانند و از آمار زمانی و رتبه‌بندی حذف می‌شوند. برای ثبت تاریخ واقعی، ابتدا شروع صنف وارد شود. زمان تدریس نامشخص و شمار فعلی شاگردان کلاس‌هایی که گزارش ندارند باید بازبینی شوند. فایل SQL اصلی تغییر نمی‌کند. برای انتقال/حذف چندمجموعه‌ای و بازیابی بکاپ، MongoDB replica set لازم است؛ Atlas این امکان را دارد.

## بکاپ

در تنظیمات، خروجی JSON نسخه‌دار شامل تمام اطلاعات کاری دریافت می‌شود؛ رمز کاربران و نشست‌ها صادر نمی‌شوند. بازیابی فقط روی فضای کاری خالی و با کنترل ارجاع‌ها، اعتبارسنجی و تراکنش انجام می‌شود. حساب‌ها و دعوت‌ها در بکاپ کاری صادر نمی‌شوند و ورود ایمیلی مستقل از آن است.

## خروجی گزارش‌ها

دکمهٔ «خروجی اکسل» فایل واقعی `.xlsx` می‌سازد. فایل شامل نام مجموعه، دورهٔ گزارش‌دهی، فیلترهای انتخاب‌شده، سربرگ رنگی، بوردر، ردیف‌های یک‌درمیان، متن‌های چندخطی و جمع آمار است. تمام ردیف‌های مطابق فیلتر صادر می‌شوند، حتی اگر در صفحهٔ دیگری از جدول باشند. در فارسی جهت برگه راست‌چین و تاریخ با قالب شمسی Excel است؛ در انگلیسی چپ‌چین و میلادی است. تاریخ‌ها و اعداد نوع اصلی خود را برای مرتب‌سازی و محاسبه حفظ می‌کنند. سربرگ هنگام اسکرول ثابت می‌ماند و چاپ برای کاغذ A4 افقی تنظیم شده است.

## کنترل کیفیت

در Vercel متغیرهای `MONGODB_URI` و `MONGODB_DB` را برای محیط Production تنظیم کنید و پس از تغییر آن‌ها Redeploy انجام دهید. مقدار URI فقط خود آدرس اتصال است؛ نام متغیر، کوتیشن یا خط جدید نباید بخشی از مقدار باشد. کاراکترهای ویژهٔ رمز داخل URI باید URL-encode شوند، مثلاً `#` به `%23` تبدیل می‌شود. مقدارهای واقعی اتصال فقط در تنظیمات خصوصی محیط نگهداری می‌شوند.

خطای `MongoParseError` یا کد `DATABASE_CONFIGURATION_ERROR` یعنی فرمت تنظیمات اتصال درست نیست؛ این خطا قبل از اتصال به دیتابیس رخ می‌دهد. کدهای `DATABASE_NOT_CONFIGURED`، `DATABASE_AUTH_FAILED`، `DATABASE_PERMISSION_DENIED` و `DATABASE_UNREACHABLE` به‌ترتیب تنظیمات ناقص، خطای احراز هویت دیتابیس، دسترسی ناکافی و مشکل اتصال شبکه را مشخص می‌کنند. لاگ سرور فقط دستهٔ خطا و کد عددی MongoDB را ثبت می‌کند و رشتهٔ اتصال، رمز و متن خام خطا را نمایش نمی‌دهد.

```powershell
npm run typecheck
npm run lint
npm test
npm run test:integration
npm run test:e2e
npm run build
npm run check:db
```

اگر سرور توسعه از قبل اجراست، برای تست مرورگر ابتدا `npm run build` را اجرا و در PowerShell متغیر `$env:E2E_USE_BUILD = "1"` را تنظیم کنید؛ سپس `npm run test:e2e` سرور تست را از همان ساخت نهایی روی پورت ۳۱۰۰ بالا می‌آورد. حساب‌ها و داده‌های آزمون در دیتابیس موقتی ساخته و در پایان حذف می‌شوند.

دو اسکیل درخواستی `taste-skill` و `ui-ux-pro-max` نصب و برای طراحی استفاده شده‌اند. جهت طراحی `framed-sheet` با seed `124820595` است. هویت رابط از چرخهٔ هفتهٔ آموزشی و فونت IRANSansX می‌آید. تمام آیکن‌های برنامه از SVGهای اصلی Astra Icons هستند؛ نسخهٔ اصلی و مجوز MIT در `vendor/astraicons` نگهداری می‌شود و اجزای React تایپ‌دار در `src/components/icons.tsx` قرار دارند. فونت‌های ارائه‌شده در `public/fonts` قرار دارند.
