# Report Desk — نسخهٔ دوم

سیستم مدیریت صنف، نصاب، گزارش هفتگی، اساتید و نگران‌ها با Next.js App Router، TypeScript و MongoDB. رابط فارسی با تقویم هجری شمسی و RTL، رابط انگلیسی با تقویم میلادی و LTR، ساعت ۱۲ساعته و تم روشن/تاریک دارد.

## حساب‌های مستقل سرنگران‌ها

در صفحهٔ ورود، «سرنگران جدید هستید؟ ثبت‌نام کنید» را انتخاب کنید. هر سرنگران با نام، نام کاربری یکتا و رمز حداقل ۱۰ نویسه حساب می‌سازد و مستقیماً وارد فضای کاری خالی خود می‌شود. نام کاربری به بزرگی و کوچکی حروف حساس نیست. صنف‌ها، اساتید، نگران‌ها، نصاب‌ها، گزارش‌ها، آرشیف، تنظیمات و بکاپ هر حساب جدا هستند؛ نقش مدیر فقط اجازهٔ مدیریت همان فضای کاری را می‌دهد.

شناسهٔ مالک از نشست معتبر سمت سرور گرفته می‌شود. ارسال شناسهٔ یک حساب یا رکورد دیگر در URL یا بدنهٔ درخواست دسترسی ایجاد نمی‌کند. شمارهٔ صنف و نام نصاب می‌توانند در حساب‌های مختلف یکسان باشند. خروجی اکسل و آمار نیز فقط از اطلاعات همان حساب ساخته می‌شوند. خروج یا تعویض حساب، برگه‌های باز دیگر مرورگر را هم به‌روز می‌کند.

برای ارتقای دیتابیس قدیمی یک بار `npm run setup` اجرا شود. این فرمان رکوردهای بدون مالک را در یک تراکنش به حساب تعیین‌شده با `ADMIN_USERNAME` متصل می‌کند و تنظیمات قبلی را نگه می‌دارد؛ دوباره اجراکردن آن حساب‌ها یا رمزهای موجود را بازنویسی نمی‌کند. در این نصب، ارتقا اجرا و حفظ اطلاعات قبلی بررسی شده است. حساب‌های جدید هیچ نسخه‌ای از اطلاعات قبلی دریافت نمی‌کنند.

## اجرا

Node.js 22 یا جدیدتر پیشنهاد می‌شود.

دستورها را از ریشهٔ پروژه، کنار فایل `package.json`، اجرا کنید.

```powershell
npm install
# فایل .env.example را به .env کپی و اتصال MongoDB و مشخصات مدیر اولیه را تنظیم کنید.
npm run setup
npm run dev
```

نشانی: http://localhost:3000/fa و http://localhost:3000/en

اگر پورت ۳۰۰۰ اشغال باشد، Next.js پورت دیگری مثل ۳۰۰۱ انتخاب می‌کند؛ نشانی بخش `Local` در ترمینال را باز کنید، مثلاً http://localhost:3001/fa. آدرس `0.0.0.0` برای گوش‌دادن سرور روی شبکه است؛ در مرورگر همین سیستم از `localhost` استفاده کنید. برای بستن اجرای قبلی، در ترمینال همان اجرا `Ctrl+C` بزنید.

`setup` ایندکس‌ها و مدیر اولیه را می‌سازد و رمز مدیر موجود را بازنویسی نمی‌کند. `ADMIN_PASSWORD_HASH` برای حفظ رمز مدیر نسخهٔ قبلی پشتیبانی می‌شود. هیچ رمز یا رشتهٔ اتصال نباید وارد Git شود. Atlas باید اتصال IP سیستم را مجاز کرده باشد. حساب MongoDB باید روی دیتابیس `report_desk` دسترسی خواندن/نوشتن داشته باشد.

## ساختار

- `src/app/api`: احراز هویت، API موجودیت‌ها، تنظیمات و پشتیبان‌گیری/بازیابی.
- `src/lib`: اتصال دیتابیس، اعتبارسنجی Zod، تقویم، منطق آمار و رتبه‌بندی.
- `src/components`: رابط کاربری، فرم‌ها، نمودارها و صفحات.
- `scripts`: راه‌اندازی و انتقال SQL قدیمی.
- `tests`: آزمون تقویم، اعتبارسنجی و رتبه‌بندی.

## منطق زمان و آمار

- هفته از جمعه شروع می‌شود و پنج‌شنبه ساعت ۱۱:۵۹ شب به وقت کابل پایان می‌یابد.
- تاریخ‌ها در دیتابیس به‌شکل میلادی `YYYY-MM-DD` ذخیره می‌شوند؛ تقویم شمسی فقط تبدیل نمایشی/انتخاب تاریخ است.
- فیلتر ماه شامل سال و تقویم انتخاب‌شده است؛ مرز ماه شمسی به تاریخ میلادی تبدیل می‌شود.
- هر صنف در هر هفته یک گزارش فعال دارد. ایندکس یکتا از ثبت تکراری هم‌زمان جلوگیری می‌کند.
- زمان اولین ارسال با ویرایش تغییر نمی‌کند. صنف یا هفتهٔ یک گزارش تاریخ‌دار قابل جابه‌جایی نیست.
- «ثبت‌نام صنف‌ها» مجموع ظرفیت فعلی صنف‌ها است و تعداد افراد یکتا نیست. «مجموع حاضری» تعداد حضور در گزارش‌ها است.
- نرخ حاضری = مجموع حاضران / مجموع شاگردان مورد انتظار، نه میانگین سادهٔ درصد صنف‌ها.
- رتبه‌بندی به‌صورت پیش‌فرض ۸ هفتهٔ تکمیل‌شده را بررسی می‌کند: ۵۰٪ گزارش به‌موقع، ۳۵٪ حاضری، ۱۵٪ ثبات حاضری. هفتهٔ باز کنار گذاشته می‌شود و هفتهٔ بدون گزارش امتیاز را کم می‌کند. بدون سابقهٔ کافی، امتیاز «—» است.
- تغییر مسئول صنف برای تاریخچه ثبت می‌شود و مشخصات مسئول هنگام گزارش نیز حفظ می‌شود.
- آرشیف صنف به گزارش‌های آن به ارث می‌رسد؛ بازیابی صنف گزارش‌های مستقلاً آرشیف‌شده را بازنمی‌گرداند.
- عناوین درس شناسهٔ ثابت و بازهٔ صفحه دارند. عنوان استفاده‌شده در گزارش قابل حذف نیست.

## انتقال نسخهٔ قدیمی

```powershell
npm run migrate -- "E:\gozaresh_db.sql"
# پس از بررسی پیش‌نمایش؛ مقصد باید خالی باشد:
npm run migrate -- "E:\gozaresh_db.sql" --apply
# برای واردکردن در حساب دیگری که از قبل ساخته شده است:
npm run migrate -- "E:\gozaresh_db.sql" --apply --username=supervisor2
```

این ابزار SQL را اجرا نمی‌کند؛ فقط داده‌های INSERT سه جدول شناخته‌شده را می‌خواند. سال و زمان ارسال برای دادهٔ بدون تاریخ حدس زده نمی‌شود. گزارش‌های بدون تاریخ در بخش گزارش‌های قدیمی باقی می‌مانند و از آمار زمانی و رتبه‌بندی حذف می‌شوند. برای ثبت تاریخ واقعی، ابتدا شروع صنف وارد شود. زمان تدریس نامشخص و شمار فعلی شاگردان کلاس‌هایی که گزارش ندارند باید بازبینی شوند. فایل SQL اصلی تغییر نمی‌کند. برای انتقال/حذف چندمجموعه‌ای و بازیابی بکاپ، MongoDB replica set لازم است؛ Atlas این امکان را دارد.

## بکاپ

در تنظیمات، خروجی JSON نسخه‌دار شامل تمام اطلاعات کاری دریافت می‌شود؛ رمز کاربران و نشست‌ها صادر نمی‌شوند. بازیابی فقط روی فضای کاری خالی و با کنترل ارجاع‌ها، اعتبارسنجی و تراکنش انجام می‌شود. حساب‌های مدیر جداگانه با `setup` ایجاد می‌شوند.

## خروجی گزارش‌ها

دکمهٔ «خروجی اکسل» فایل واقعی `.xlsx` می‌سازد. فایل شامل نام مجموعه، دورهٔ گزارش‌دهی، فیلترهای انتخاب‌شده، سربرگ رنگی، بوردر، ردیف‌های یک‌درمیان، متن‌های چندخطی و جمع آمار است. تمام ردیف‌های مطابق فیلتر صادر می‌شوند، حتی اگر در صفحهٔ دیگری از جدول باشند. در فارسی جهت برگه راست‌چین و تاریخ با قالب شمسی Excel است؛ در انگلیسی چپ‌چین و میلادی است. تاریخ‌ها و اعداد نوع اصلی خود را برای مرتب‌سازی و محاسبه حفظ می‌کنند. سربرگ هنگام اسکرول ثابت می‌ماند و چاپ برای کاغذ A4 افقی تنظیم شده است.

## کنترل کیفیت

در Vercel متغیرهای `MONGODB_URI` و `MONGODB_DB` را برای محیط Production تنظیم کنید و پس از تغییر آن‌ها Redeploy انجام دهید. مقدار URI فقط خود آدرس اتصال است؛ نام متغیر، کوتیشن یا خط جدید نباید بخشی از مقدار باشد. کاراکترهای ویژهٔ رمز داخل URI باید URL-encode شوند، مثلاً `#` به `%23` تبدیل می‌شود. مقدارهای واقعی اتصال فقط در تنظیمات خصوصی محیط نگهداری می‌شوند.

خطای `MongoParseError` یا کد `DATABASE_CONFIGURATION_ERROR` یعنی فرمت تنظیمات اتصال درست نیست؛ این خطا قبل از اتصال به دیتابیس رخ می‌دهد. کدهای `DATABASE_NOT_CONFIGURED`، `DATABASE_AUTH_FAILED`، `DATABASE_PERMISSION_DENIED` و `DATABASE_UNREACHABLE` به‌ترتیب تنظیمات ناقص، خطای احراز هویت دیتابیس، دسترسی ناکافی و مشکل اتصال شبکه را مشخص می‌کنند. لاگ سرور فقط دستهٔ خطا و کد عددی MongoDB را ثبت می‌کند و رشتهٔ اتصال، رمز و متن خام خطا را نمایش نمی‌دهد.

```powershell
npm run typecheck
npm run lint
npm test
npm run test:integration
npm run test:e2e
npm run build
npm run check:db
```

اگر سرور توسعه از قبل اجراست، برای تست مرورگر ابتدا `npm run build` را اجرا و در PowerShell متغیر `$env:E2E_USE_BUILD = "1"` را تنظیم کنید؛ سپس `npm run test:e2e` سرور تست را از همان ساخت نهایی روی پورت ۳۱۰۰ بالا می‌آورد. حساب‌ها و داده‌های آزمون در دیتابیس موقتی ساخته و در پایان حذف می‌شوند.

دو اسکیل درخواستی `taste-skill` و `ui-ux-pro-max` نصب و برای طراحی استفاده شده‌اند. جهت طراحی `framed-sheet` با seed `124820595` است. هویت رابط از چرخهٔ هفتهٔ آموزشی و فونت IRANSansX می‌آید. تمام آیکن‌های برنامه از SVGهای اصلی Astra Icons هستند؛ نسخهٔ اصلی و مجوز MIT در `vendor/astraicons` نگهداری می‌شود و اجزای React تایپ‌دار در `src/components/icons.tsx` قرار دارند. فونت‌های ارائه‌شده در `public/fonts` قرار دارند.
